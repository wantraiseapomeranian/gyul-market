# 귤상회 PROJECT

> 무엇을, 왜 만드는지와 범위를 정의한다. 화면·토큰은 [DESIGN.md](DESIGN.md), 구현 순서는 [PLAN.md](PLAN.md), 검증 기준은 [TEST_PLAN.md](TEST_PLAN.md)에 있다.
> 상태: Phase 3 초안 · 2026-11-05 · G3 승인 전

## 1. 목표

카카오톡 오픈프로필 링크로 들어온 사람이 **실제 제주 감귤 쇼핑몰이라고 믿게** 한 뒤, 귤 당도 검사 미니게임을 거쳐 **"귤은 없습니다."** 를 공개하고 친구에게 공유하게 만드는 비상업 유머 페이지.

| 성공 기준 | 측정 방법 |
|---|---|
| 첫 화면이 실제 국내 신선식품몰처럼 보인다 | 실제 쇼핑몰 캡처와 나란히 놓고 비교(TEST_PLAN §8), 사용자 승인 |
| 진입부터 엔딩까지 15~25초 | 첫 화면에서 CTA를 바로 누를 때 기준, 실기기 측정 |
| 반전이 이해되고 공유된다 | 엔딩에서 공유 버튼이 가장 큰 행동, 공유 링크가 상품 화면에서 다시 시작 |
| AI가 만든 쇼핑몰 템플릿처럼 보이지 않는다 | DESIGN.md §9 감사 기준 통과 |

## 2. 사용자 시나리오

**S1. 처음 방문한 사람 (주 시나리오)**
1. 카카오톡 프로필의 링크 미리보기(사진 + "제주 서귀포 햇귤 10kg")를 보고 누른다.
2. 카카오톡 인앱 브라우저에서 상품 상세가 열린다. 사진, 가격, 배송 정보, 선별 태그를 본다.
3. 하단 버튼 **당도 검사 받기**를 누른다.
4. 당도 검사표에서 귤 A·B·C 중 하나를 고른다.
5. 귤을 5번 눌러 측정한다. 누를 때마다 도장이 찍히고 당도계 바늘이 오른다.
6. 검사 결과(예: 15.8 °Bx)를 확인하고 **최종 판정 받기**를 누른다.
7. 판정서가 올라오며 도장이 찍히고, **"귤은 없습니다."** 판정서가 나온다.
8. **친구도 검사받게 하기**로 공유하거나, 다시 검사한다.

**S2. 공유받은 사람**: 링크 미리보기는 S1과 같다. 결과가 스포일러되지 않고 상품 상세부터 시작한다.

**S3. 다시 하는 사람**: 엔딩이나 결과에서 다시 검사하면 검사표로 돌아가고, 당도 배정이 새로 섞인다.

## 5. 표기 원칙 (정직성)

낚시는 **"쇼핑몰처럼 보이는 것"** 까지만 한다. 구매 진입(구매하기 → 수량·총액 → 당도 검사 안내)까지는 보여 주지만(D5), 결제 수단·배송지 입력·주문 접수/결제 완료 연출 같은 실제 거래는 흉내 내지 않는다. 생산 이력·법정 표시도 흉내 내지 않는다.

- **쓰지 않는 것**
  - 구매 후기, 구매자·재구매 수, 재고·마감 임박, 할인 전 가격(취소선)
  - 원산지 표시 행, 상품정보제공고시, 생산자·소재지, 수확일, 로트·일련번호 같은 생산 이력
  - 입력 폼, 결제 수단 로고
- **쓰는 것**
  - 상품명·카피 속 지명("제주 서귀포 햇귤")은 콘셉트 표현으로 유지한다.
  - 검사표·판정서의 문서번호와 날짜는 **게임 서류**의 번호이고, 날짜는 플레이한 당일이다.
  - 규격(2S·S·M)은 크기 등급이고, 당도는 연출 수치다. 두 값을 같은 줄에서 인과처럼 말하지 않는다.
- **고지 위치**: FR-15
